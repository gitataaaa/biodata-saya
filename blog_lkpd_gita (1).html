Analisis: Cara Kirim Data ke View

Cara 1 — Array Asosiatif

  • Terorganisir rapi dalam 1 variabel
  • Mudah dikembangkan (scalable)
  • Konsisten dengan pattern Laravel
  • Lebih mudah dibaca
  • − Harus buat array manual dulu
  • − Kurang fleksibel untuk data terpisah

Cara 2 — compact()

  • Syntax lebih ringkas dan cepat
  • Tidak perlu buat array manual
  • Praktis untuk data sedikit
  • − Kurang terorganisir jika banyak data
  • − Rawan error jika variabel tidak ada
  • − Sulit dikembangkan jika data bertambah

Edit & Delete Data with Facade DB

Fungsi update() dan destroy() pada Controller

Edit Delete update() destroy() old()
Studi Kasus 1 Jelaskan isi dari fungsi update() dan destroy() pada SiswaController.

update()

  • Menerima input data baru dari form
  • Melakukan validasi data
  • Mencari record berdasarkan ID
  • Menyimpan perubahan ke database
  • Redirect dengan success message

destroy()

  • Menerima ID data yang dihapus
  • Mencari record berdasarkan ID
  • Menghapus record secara permanen
  • Bisa menggunakan soft delete
  • Redirect dengan success message
Studi Kasus 2 Implementasikan Edit dan Delete untuk tabel t_kelas.
edit() & update() — KelasController
KelasController.php
public function edit($id) {
    $kelas = DB::table('t_kelas')->where('id', $id)->first();
    return view('Kelas.form', compact('kelas'));
}

public function update(Request $request, $id) {
    $request->validate([
        'nama_kelas'      => 'required',
        'jurusan'         => 'required',
        'lokasi_ruangan'  => 'required',
        'nama_wali_kelas' => 'required',
    ]);
    DB::table('t_kelas')->where('id', $id)->update([
        'nama_kelas'      => $request->nama_kelas,
        'jurusan'         => $request->jurusan,
        'Nama_Wali_Kelas' => $request->nama_wali_kelas,
        'Lokasi_Ruangan'  => $request->lokasi_ruangan,
    ]);
    return redirect()->route('kelas.index')
        ->with('success', 'Data berhasil diperbarui!');
}

public function destroy($id) {
    DB::table('t_kelas')->where('id', $id)->delete();
    return redirect()->route('kelas.index')
        ->with('success', 'Data berhasil dihapus');
}

Eloquent ORM

Model, mass assignment, CRUD menggunakan ORM

Eloquent Model $fillable ORM Mass Assignment

$table

Variabel untuk menentukan nama tabel pada database yang digunakan oleh model ini.

$fillable

Variabel untuk menentukan field apa saja yang boleh di-fill / di-insert melalui mass assignment.

Studi Kasus 1 Lakukan CRUD (Create, Edit, Delete) untuk tabel t_kelas menggunakan Eloquent.

namespace App\Models;
use Illuminate\Database\Eloquent\Model;

class Kelas extends Model {
    public $table = 't_kelas';
    protected $fillable = ['nama_kelas', 'jurusan', 'lokasi_ruangan', 'nama_wali_kelas'];
}

class Guru extends Model {
    use HasFactory;
    protected $table    = 't_guru';
    protected $fillable = ['nip', 'nama_guru', 'mata_pelajaran', 'alamat'];
}
GuruController.php — store() dengan ORM create()
public function store(Request $request) {
    $rule = [
        'nip'            => 'required|string|unique:t_guru,nip',
        'nama_guru'      => 'required|string',
        'mata_pelajaran' => 'required|string',
        'alamat'         => 'required',
    ];
    $this->validate($request, $rule);
    $status = Guru::create($request->all());

    if ($status) {
        return redirect('/guru')->with('success', 'Data guru berhasil ditambahkan');
    }
}

public function update(Request $request, $id) {
    $guru   = Guru::findOrFail($id);
    $status = $guru->update($request->all());

    if ($status) {
        return redirect('/guru')->with('success', 'Data guru berhasil diubah');
    }
}

Studi Kasus 3 Jelaskan perbedaan signifikan antara DB Facade dan Eloquent.
Eloquent ORM unggul dalam kemudahan penulisan dan manajemen relasi berbasis OOP namun lebih lambat, sementara DB Facade jauh lebih cepat dan hemat memori karena bekerja lebih dekat dengan SQL mentah namun kodenya lebih manual.

Eloquent ORM

  • Berbasis objek (OOP), lebih intuitif
  • Mudah mengelola relasi antar tabel
  • Kode lebih bersih dan readable
  • Mendukung event & observer
  • − Lebih lambat (overhead ORM)
  • − Lebih boros memori

DB Facade

  • Lebih cepat, lebih dekat ke SQL
  • Hemat memori
  • Cocok untuk query kompleks
  • Performa tinggi untuk data besar
  • − Kode lebih manual & verbose
  • − Relasi lebih sulit dikelola
