📌 Penjelasan Status Code 200 OK

Status code 200 OK adalah respon HTTP yang artinya request berhasil diproses oleh server. Ketika Postman menampilkan 200 OK pada endpoint GET /api/siswa, itu berarti: (1) Server Laravel berhasil menerima request, (2) Controller berhasil mengambil data dari database, dan (3) Data berhasil dikembalikan dalam format JSON. Ini adalah status yang kita harapkan untuk setiap operasi GET yang sukses.

Bagian 02

Fetch Data dengan async/await

Membuat skrip JavaScript untuk mengambil data dari API menggunakan pendekatan asynchronous.

2
Fungsi fetch() dengan async/await & Hasil console.log()
Tugas: Buatlah skrip JavaScript untuk memanggil data dari API menggunakan async/await agar main thread tidak terhenti saat menunggu data dari server. Lampirkan potongan kode dan hasil console.log().
script.js
const API_URL = "http://127.0.0.1:8000/api/siswa";

// Soal 1 & 2 — Fetch & Tampilkan Data
async function fetchDataSiswa() {
  try {
    const response = await fetch(API_URL);

    // Cek error status (404, 500, dll)
    if (!response.ok) {
      throw new Error(`Error ${response.status}: ${response.statusText}`);
    }

    const data = await response.json();
    console.log("Data siswa:", data); // Soal 2 — bukti console.log
    tampilkanData(data);           // Soal 3
  } catch (error) {
    // Error handling
    tampilkanPesan("Gagal memuat data: " + error.message, "red");
    console.error("Error:", error);
  }
}

💡 Mengapa async/await?

Proses pengambilan data dari server membutuhkan waktu. Tanpa async/await, JavaScript akan terus menjalankan baris berikutnya sebelum data datang, menyebabkan bug. Dengan await, program "menunggu" hingga data siap tanpa membekukan tampilan browser (main thread tetap responsif). Ini adalah cara modern menangani operasi asynchronous yang lebih bersih dibanding callback biasa.

Bagian 03

Menampilkan Data ke Tabel HTML

Transformasi data JSON menjadi baris tabel secara dinamis menggunakan JavaScript DOM.

3
Render JSON ke Elemen <tr> Secara Dinamis
Tugas: Transformasikan data JSON menjadi elemen baris tabel (<tr>) secara dinamis. Gunakan document.createElement atau innerHTML untuk memasukkan data Nama, NIS, dan Kelas.
script.js — fungsi tampilkanData()
function tampilkanData(data) {
  const tbody = document.querySelector("#tabel-siswa tbody");
  tbody.innerHTML = ""; // Kosongkan dulu

  data.forEach((siswa, index) => {
    const row = document.createElement("tr");
    row.innerHTML = `
      <td>${index + 1}</td>
      <td>${siswa.nis}</td>
      <td>${siswa.nama_lengkap}</td>
      <td>${siswa.jenis_kelamin}</td>
      <td>${siswa.golongan_darah}</td>
      <td>
        <button onclick="editSiswa(${siswa.id})">Edit</button>
        <button onclick="hapusSiswa(${siswa.id})">Hapus</button>
      </td>
    `;
    tbody.appendChild(row);
  });
}

script.js — fungsi simpanData()
async function simpanData() {
  const id = document.getElementById("input-id").value;
  const payload = {
    nis:            document.getElementById("input-nis").value,
    nama_lengkap:   document.getElementById("input-nama").value,
    jenis_kelamin:  document.getElementById("input-jk").value,
    golongan_darah: document.getElementById("input-gol").value,
  };

  const method = id ? "PUT" : "POST";
  const url    = id ? `${API_URL}/${id}` : API_URL;

  const response = await fetch(url, {
    method,
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(payload),
  });

  if (response.ok) {
    resetForm();
    fetchDataSiswa(); // Refresh tabel
  }
}

Bagian 05

Edit & Hapus Data (PUT & DELETE)

Implementasi fitur edit dengan metode PUT dan hapus data dengan metode DELETE.

5
Logika PUT untuk Edit & DELETE untuk Hapus Data
Tugas: Implementasikan fitur edit dan delete data siswa pada setiap baris. Komunikasi HTML ke API menggunakan metode PUT dan DELETE. Jelaskan logika pengiriman data dan lampirkan buktinya.

✏️ Edit (PUT)

script.js — fungsi editSiswa()
async function editSiswa(id) {
  // Ambil data siswa berdasarkan ID
  const res  = await fetch(`${API_URL}/${id}`);
  const data = await res.json();

  // Isi form secara otomatis
  document.getElementById("input-id").value   = data.id;
  document.getElementById("input-nis").value  = data.nis;
  document.getElementById("input-nama").value = data.nama_lengkap;
  document.getElementById("input-jk").value   = data.jenis_kelamin;
  document.getElementById("input-gol").value  = data.golongan_darah;
  // simpanData() akan otomatis pakai PUT karena id tidak kosong
}

🗑️ Delete (DELETE)

script.js — fungsi hapusSiswa()
async function hapusSiswa(id) {
  // Konfirmasi sebelum hapus
  if (!confirm("Yakin ingin menghapus data ini?")) return;

  const response = await fetch(`${API_URL}/${id}`, {
    method: "DELETE",
  });

  if (response.ok) {
    fetchDataSiswa(); // Refresh tabel tanpa reload halaman
  }
}

📌 Ringkasan Logika

Fungsi simpanData() digunakan untuk dua keperluan: jika field id terisi → kirim PUT (update), jika kosong → kirim POST (tambah baru). Sementara fungsi hapusSiswa(id) mengirim request DELETE ke endpoint dengan id spesifik. Setelah setiap operasi berhasil, tabel direfresh otomatis dengan memanggil ulang fetchDataSiswa().

Bagian 06

Error Handling dengan try...catch

Menambahkan penanganan error agar aplikasi tetap informatif saat API tidak tersedia.

6
Kode try...catch & Pentingnya bagi User Experience
Tugas: Tambahkan logika try...catch untuk menangani kondisi jika API tidak ditemukan (404) atau server bermasalah (500). Jelaskan mengapa hal ini penting bagi User Experience.
script.js — error handling
try {
  const response = await fetch(API_URL);

  // Cek error status (404, 500, dll)
  if (!response.ok) {
    throw new Error(
      `Error ${response.status}: ${response.statusText}`
    );
  }

  const data = await response.json();
  tampilkanData(data);

} catch (error) {
  // Jika API tidak ditemukan atau server error
  tampilkanPesan("Gagal memuat data: " + error.message, "red");
  console.error("Error:", error);
}

Ketika terjadi error, pengguna melihat pesan yang jelas:

❌  Gagal memuat data: Error 404: Not Found
❌  Gagal memuat data: Error 500: Internal Server Error

Dibandingkan ketika sukses:

✅  Data berhasil dimuat! Menampilkan 5 siswa.

🎯 Mengapa Penting bagi User Experience?

Tanpa try...catch, ketika API gagal, pengguna akan melihat halaman kosong atau tabel yang tidak berisi data — tanpa tahu apa yang terjadi. Dengan error handling yang baik: (1) Pengguna mendapat informasi jelas bahwa ada masalah, (2) Aplikasi tidak crash total, (3) Developer bisa membaca detail error di console untuk debugging, dan (4) Pesan berwarna merah secara visual langsung menarik perhatian ke masalah yang terjadi.
